# BOC backfill report: SAMPLE run

> **This is a sample, not the full backfill.** It covers six periods spread over 2016 to 2025 (151 weekdays), chosen to cover every layout and the layout change of December 2017. The full run (2016 to 2025, about 2 600 weekdays) has not been done yet: see "Running the full backfill" below. Everything here was produced against a disposable local database, not production.

Generated by `pnpm --filter doni-backend backfill:boc` (ADR 0018) against real bulletins downloaded from brvm.org, with the seed catalogue (SNTS, ORAC, ETIT, PALC, SGBC; indices BRVM-C and BRVM-30). Every day went through the same ingestion service and automatic checks as the daily run. The backfilled prices are stored with `origin = 'backfill'` and stay hidden from users while `HISTORY_PUBLIC` is off.

The command was run three times over the same periods, which also exercised resumability:

1. first run: 81 imported, 12 held, 58 not found (213 requests);
2. same command again (resume): only the 58 days without a bulletin were requested again (114 requests); 3 of them had failed on the network the first time and were now imported. The fetcher now retries a network failure once and reports such days apart from 404s;
3. after fixing the parser for what the held days showed (numbers printed in pieces, "(d)" and "Val-T" mentions; two of those bulletins are now fixtures), `--retry-held` read the held days again: the result below.

## Running the full backfill

Against the target database (migrations applied, catalogue in place), with `HISTORY_PUBLIC` left off:

```bash
pnpm --filter doni-backend backfill:boc --from 2016-01-01 --to 2025-12-31 --report ../docs/backfill-report.md
```

At the default pause of 2 seconds before each request (at most two per weekday, plus one retry on a network failure) this takes a few hours and up to about 5 000 requests to brvm.org for some 2 600 weekdays. It can be stopped and started again at any time; run it again to retry days that failed on the network, and with `--retry-held` after a parser fix. Admins then review the held days in the bulletin review screen. Showing the history to users is a separate decision: set `HISTORY_PUBLIC=true` only once the BRVM's redistribution terms cover historical data (ADR 0003, ADR 0018).
